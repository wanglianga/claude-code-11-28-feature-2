# 企业股权关系分析平台 + 利润来源穿透与跨期对账（虚构演示）

帮助集团分析员把各子公司股东名册汇成**可追溯的持有关系**，并进一步回答：某笔上层公司的应收
金额在分析日究竟能穿透到哪些经营企业的利润来源、哪些金额只是已声明但尚无外部到账证据、
以及重述后哪些历史对账结论受影响。

本仓库在原有**股权经济权益 / 表决控制**能力之上，增加了**利润来源穿透与跨期对账**能力：

- **期间对齐器**：把利润表的会计期间、决议记录日、应收确认日、回单到账日分别建模，
  **不把同月发生视为同一会计事实**。
- **来源分配编译器**：按决议引用的股权快照与股份类别计算可解释的应收来源链；
  遇到交叉持股时保留**路径贡献与残差**，**不将循环部分重复累加**；
  记录日无可确认快照时列 **“权属待证”**，**不借用最近一期股权比例**。
- **回单匹配器**：依据外部回单号、币种、金额方向、付款主体与摘要建立候选关联，把一笔回单
  **拆分**或多笔回单**汇聚**的理由记录为事实；同一回单等额匹配两条应收且摘要无法区分时，
  保持 **一对多候选** 并从已核验到账中排除该金额。
- **跨期桥接器**：把“已声明应收 / 可核验到账 / 汇率差异 / 重述影响 / 无法归属”**分层发布**，
  不同币种不混加；无获批汇率时只发布原币与**缺失汇率提示**，不按市场汇率自行换算。
- **审计快照器**：按指定截止日封存利润来源、股权版本、决议资料与匹配结果；重述只生成跨期差异，
  **不回写原审计快照**。

三个原始问题仍保留：

1. **谁最终享有多少经济权益**——对有向持股图建立联立方程，从原始股份求解最终经济份额；
2. **哪些公司受同一方控制**——按表决权票数独立计算控制范围，严格超过半数才扩展；
3. **哪些结论因资料不足还不能确定**——完全封闭持股报告"不可唯一求解"，未知持有人保留独立份额。

> **免责声明**：平台内所有企业、自然人、机构股东、利润表、决议、应收、回单、汇率及名册均为
> **虚构样本**，不连接任何工商网站或银行，不构成真实投资、税务或法律结论。
> 统一社会信用代码、证件号、文号、回单号均为编造。**系统不执行分红批准、现金预留、银行付款、
> 退款或余额扣还**——只登记与发布可复算的财务事实。

## 一、技术栈与架构

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 前端 | React 18 + TypeScript + Vite | 利润穿透对账、财务事实资料、经济权益与表决控制并列展示 |
| 后端 | Python 3.12 + FastAPI + SQLAlchemy 2（异步） | REST API，自带 OpenAPI 3.x / Swagger UI |
| 数据库 | PostgreSQL 18 | 修订、名册、利润表、决议、快照、匹配、审计封存全部可追溯 |
| 数值 | NumPy（SVD）+ Fraction 有理数 | 股权联立方程求解；来源分配用精确有理数，残差可手算复核 |

```
frontend (nginx/Vite)  ──/api──▶  backend (FastAPI)  ──▶  PostgreSQL
```

核心算法纪律：

- **先 SCC 后联立**：Tarjan 找出互相持股的强连通分量；对每个公司建立
  `x[i,h] = b[i,h] + Σ_j A[i,j]·x[j,h]`，矩阵形式 `(I−A)X=B`，SVD 求解。
- **封闭不近似**：完全封闭、无法分配到外部主体的 SCC 报告 `non_unique`，
  **不限制遍历深度、不给近似百分比**。
- **未知不归一**：未知持有人是独立的 B 列，已知部分不会被重新归一成 100%。
- **数值不稳定即停**：秩亏损、条件数超限、残差或权益合计超容差时停止正式出数并列出公司。
- **控制另算**：以直接可行使票数为起点，只累计**已确认受控公司**的票数，
  严格 `>50%` 才扩展并迭代到不动点；环形持股无法靠"假定彼此受控"自举。
- **权属只认记录日快照**：来源分配只采用决议记录日当天、状态可确认的股权快照；
  缺失即"权属待证"，**绝不借用最近一期比例**。
- **残差单列不重复累加**：交叉持股穿透再次遇到已访问公司时，该部分记为循环残差，停止递归。
- **回单一对多不核验**：等额冲突且摘要无法区分时保持候选、排除出已核验到账。
- **汇率只认获批来源**：无获批汇率时只发布原币金额与缺失提示。
- **重述不回写**：已封存的审计快照内容由哈希固定，重述只出现在新的跨期差异中。

## 五、四个股权演示场景与手算样本

### 场景 1：交叉持股可求解（甲 A / 乙 B）

- A：张东明 600、B 持 400（总量 1000）；B：A 持 200、晨星 800（总量 1000）。
- 联立：`I−A = [[1,−0.4],[−0.2,1]]`，行列式 `0.92`。
- 张东明在 A 的最终份额 `0.6/0.92 = 0.65217391`；晨星在 B 为 `0.8/0.92 = 0.86956522`。
- 测试 `test_cross_holding_solvable_by_hand` 逐项断言，页面可点开"方程贡献"查看 A_ij·x_jh。

### 场景 2：完全封闭不可确定（丙 C / 丁 D）

- C：D 持 60%、自持 40%；D：C 持 100%。无任何外部渗入。
- 系统判定封闭 SCC，输出 `non_unique` 与不可分配份额 1.0，**不产生近似百分比**
  （`test_closed_loop_non_unique`）。

### 场景 3：股权与票权分离（戊 F → 己 G → 庚 H）

- F：普通股 6000（一股一票）+ 优先股 4000（一股十票），总票数 46000。
- 王辅庭经济权益仅 40%，却持 40000 票（86.96%）直接控制 F；
  F 控制 G（51%），G 控制 H（60%），控制经两轮不动点扩展到 H
  （`test_control_vote_equity_separation_and_expansion`）。

### 场景 4：增资更正（辛 K）

- 增资前 V1：总量 1000 股，有效期至 2025-06-30；增资后 V2：总量 2000 股，更正 V1。
- 时点 `2025-03-15` 只取 V1，时点 `2026-03-01` 只取 V2，**两份绝不拼成一次分析**；
- V2 导入后，引用 V1 的待发布运行立即置 `stale` 且禁止发布，历史报告保留 V1 来源快照
  （`test_correction_expires_draft_run_but_history_kept`）。

另有：寅制造 R 含一行负股份 → `partial_failed`，修正后从断点续导成功才可审核；
癸商贸 O 两个同名"恒信顾问"标识不一致 → 冲突候选，人工确认也被 409 拒绝。

## 六、八个财务穿透验收场景与手算样本

财务样本在 `backend/app/seed_finance.py` 中幂等播种，金额与文号均为虚构。
所有期望值均由手算独立推导，并由 `tests/test_finance.py` / `tests/test_finance_api.py` 断言。

### C1 交叉持股残差（40 = 32 + 6.4 + 1.6）

- 乙产业 FY2025 利润 = 经营 4000 + 对甲集团分红收益 1000 = 5000；
  甲集团 FY2025 利润 = 经营 800 + 对乙产业分红收益 200 = 1000。
- 应收 `AR-B-2026-01` 40 万元（乙产业 → 甲集团）穿透：
  - 第一层 乙：经营 `40 × 4000/5000 = 32`；对甲分红收益 `40 × 1000/5000 = 8` 进入甲；
  - 第二层 甲：经营 `8 × 800/1000 = 6.4`；对乙分红收益 `8 × 200/1000 = 1.6` **再次遇乙 → 残差**；
  - 合计 `32 + 6.4 + 1.6 = 40`，权重 `0.8 + 0.16 + 0.04 = 1`，**循环部分未重复累加**。

### C2 跨期到账（按会计期间而非同月）

- 应收 `AR-F-2025-12-001` 确认日 `2025-12-31`（FY2025），回单 `RCPT-XP-...` 到账日 `2026-01-05`（2026-H1）；
- 期间对齐器判定 **FY2025 → 2026-H1 跨期**，并分别列出两边会计期间，不按“同月”视为同一事实。

### C3 回单一对多冲突

- 回单 `RCPT-H-50` 50 万元等额匹配 `AR-H-2026-01A` 与 `AR-H-2026-01B` 两条应收，摘要空白；
- 系统保持**一对多候选**、两条均 `verified=false`，并从“已核验到账”中**排除该 50 万元**。

### C4 回单拆分

- 应收 `AR-B-SPLIT-1201` 120 万元，由回单 `RCPT-SPLIT-1` 70 万 + `RCPT-SPLIT-2` 50 万两张到账；
- 两条匹配 `status=split`，**拆分理由作为事实记录**，合计恰为 120。

### C5 回单汇聚

- 一张回单 `RCPT-AGG-150` 150 万元，摘要点名两张应收 `AR-B-AGG-0901`(90) 与 `AR-B-AGG-0601`(60)；
- 两条匹配 `status=aggregated`，**汇聚理由作为事实记录**，合计恰为 150。

### C6 利润重述

- 辛股份 FY2025 原利润 350（经营 300 + 其他 50），审计后重述为 300（经营 250 + 其他 50）；
- 重述影响 `−10 CNY` = 应收 60 / 原利润 300 × 差额 −50；旧表置 `superseded` 但**保留原值**；
- 已封存审计快照的 `frozen_json` 与哈希**不被回写**（`test_restatement_does_not_rewrite_sealed_audit_snapshot`）。

### C7 汇率缺失 vs 已获批换算

- USD 应收 25 万元仅有 **未获批** 汇率（`approved=false`）→ 只发布原币 25 USD 与缺失提示，
  **不按市场汇率自行换算**，`reporting_amount=null`；
- EUR 应收 10 万元有两条获批汇率（确认日 7.80、到账日 7.85）→ 换算差异
  `10 × (7.85 − 7.80) = 0.50 CNY`，按获批来源折算。

### C8 权属待证

- 甲集团决议 `RES-A-2025-11` 记录日 `2025-11-30`，系统中**没有该日的可确认股权快照**；
- 相关应收 `AR-A-2025-11` 列为 **“权属待证”**，**不借用最近一期（2026-01-15）股权比例**。

## 八、关键业务规则落点

- 每份名册带公司标识、股本类别、股份数、每股表决权、有效区间、出处（见导入模板）。
- 同名仅生成候选；统一社会标识不一致禁止自动归并，冲突候选由后端强制拦截。
- 审核时强制"同类别股份合计 = 登记总量"，不符即驳回；失败行未续导完成不得审核。
- 导入按 `source_ref + SHA-256 内容指纹`识别重复/更正/撤回，事件全程留痕。
- 所有分析结果挂在修订与名册快照上，可追溯到原始出处；更正只使**待发布**结果过期，
  已发布历史报告只读保留。
- **四类日期分别落库**：利润表 `period_start/period_end`、决议 `record_date`、
  应收 `confirmed_date`、回单 `value_date`；期间对齐只按会计期间判跨期。
- **权属只认记录日快照**：`EquitySnapshot.snapshot_date == resolution.record_date` 且状态可确认，
  否则列权属待证；收款主体须在快照对应股份类别中出现。
- **来源链逐链可追溯**：每条链记录利润表行 id、付款公司路径、路径权重、金额与残差理由。
- **回单事实**：拆分/汇聚/一对多冲突的 `reason` 与 `detail_json` 均落库，一对多排除出核验。
- **汇率闸门**：仅 `approved=true` 且有 `rate` 的汇率可用；缺失只发布原币与提示。
- **审计封存**：`AuditSnapshot.frozen_json` 由 SHA-256 固定，重述不回写；封存后运行只读。
- **不做资金动作**：系统无分红批准、现金预留、银行付款、退款或余额扣还端点。
- 容差与数值阈值可通过环境变量调整：`EQUATION_TOLERANCE`、`SINGULAR_THRESHOLD`、`CONDITION_LIMIT`。
